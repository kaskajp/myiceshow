# Skinned character fixture

Status: **project-authored import/deformation study, not production character art or approved skating animation**.

## What it proves

The lab bundles `MyIceShow/Assets/SkaterFixture.usdz`. RealityKit imports its skeleton, bind/rest transforms, weighted geometry, and named materials. Studio's **Imported skin** and **Articulated** buttons compare the skin with the fixed-length primitive mannequin at the same sampled time. The imported skin is the default study appearance.

The fixture has 15 joints, 1,534 authored vertices, 2,568 triangles, and six material groups: Costume, Leggings, Skin, Boots, Blades, and Hair. The generated package is approximately 46 KB. RealityKit currently merges these groups into one skinned `ModelEntity`, preserving its material names and joint paths. The loader validates that import shape rather than assuming any arbitrary character has it.

The limbs use blended weights around knees and elbows. Torso weights span pelvis and spine. Head/hair, hands, boots, and blades have rigid attachments within the same skeletal binding. These simple forms expose import and deformation issues; they do not establish production skin weights, anatomical proportions, garment quality, or a connected whole-body topology.

## Generation and provenance

The geometry and weights are generated by `tools/generate-skater-fixture.py`, written for this repository. No marketplace character, coaching video, downloaded mesh, texture, or external animation is incorporated. Project licensing is unchanged; this fixture does not settle the rights needed for future production assets.

Normal app builds use the bundled package. Regenerate it on macOS with Python 3 and Apple's installed `usdchecker` / `usdzip` tools:

```sh
python3 tools/generate-skater-fixture.py
```

The generator builds a temporary USDA stage, validates it with `usdchecker --arkit`, packages it with `usdzip --arkitAsset`, validates the package, and then replaces the fixture. It uses Python's standard library only; there is no Python or USD-tool dependency inside the iOS app. The mesh/skeleton definition is reproducible from source; archive bytes may differ with packaging tools or metadata.

## Coordinate contract

- Y-up, local +Z-forward, meters, ice plane at zero.
- Identity bind-pose joint rotations and unit scale. Bind transforms are skeleton-space translations; rest transforms are parent-local translations.
- A straight-limbed rest pose with the pelvis at 1.06 meters and ankles at 0.08 meters. The sampled neutral pose bends the knees; rest pose and performance pose are deliberately different.
- Thigh/shin lengths match `SkaterRig`: 0.5 / 0.48 meters. Upper-arm/forearm lengths are 0.27 / 0.25 meters.
- Full joint paths identify joints; neither imported material order nor an unnamed material index identifies the costume.

`SkaterSkeleton` maps the current `SkaterPose` into desired skeleton-space joint frames, then converts them into parent-local translations and rotations. Thigh/shin and upper-arm/forearm axes align with their current limb directions. Ankle orientation remains level in skater-local space so the fixture's blades stay horizontal. Bone twist uses minimal axis alignment, not an anatomical twist solver.

`ImportedSkater` validates the joint schema, transform count, and named costume material before reporting readiness. It maps imported joint order to the sampler's order, assigns `jointTransforms`, and updates only the named costume slot. Import happens asynchronously; dismantling the rink cancels its loading task. Missing assets, incompatible skeletons, and missing costume materials produce explicit errors. Studio does not silently substitute primitives: the user can select Articulated if importing fails.

The same skater root receives the circular travel, jump height, heading, and spin-contact placement correction in either appearance. Appearance is a lab display choice, not saved show content. Switching it does not reset the routine or its playback position.

The package's `Rest` skeleton animation only supplies a bind/rest fixture. It contains **no authored skating animation clips**. Runtime joints come from the existing absolute-time procedural sampler; no independent animation playback clock is started. Seeking or replaying therefore computes the same joint transforms rather than accumulating frame-dependent rotations.

## Verification

- Both the USDA stage and USDZ package passed `usdchecker --arkit`.
- A native RealityKit import probe found the expected skeleton and named materials. Imported rest leg lengths and ankle height matched the pose rig; a sampled lunge was assigned through the actual imported model's joint transforms.
- The probe explicitly rejected a missing bundled asset, an incompatible skeleton, and a missing costume material.
- An ad-hoc Swift harness reconstructed skeleton-space joints from **7,515 parent-local poses** across the five moves at minimum/default/maximum durations. Joint-position and level-ankle errors stayed below 0.00001 scene units. The harness also checked bone-axis alignment and unit quaternions.
- The existing spin-contact, transition, fixed-length, jump-timing, and deterministic-seek harness passed again. These are ad-hoc checks, not a configured test target.
- The simulator build passed. On iPhone 16 Pro / iOS 18.6, the imported skin loaded, playback advanced through the five study moves, and the low lunge was visually inspected. Switching appearances while paused preserved the displayed time; the imported torso changed to Seafoam without recoloring the rest of the character.
- Scrubbing backwards from the lunge at approximately 15 seconds selected the upright-spin pose at approximately eight seconds while remaining paused. Playback resumed from there and returned to Play at the 18-second endpoint.
- Temporarily moving the installed simulator bundle's USDZ aside produced the visible missing-asset error. Selecting Articulated explicitly selected the primitive study instead. The resource was restored immediately, compared with the built asset, and normal import succeeded after relaunch. No saved-show archive was modified for this check.

An initial segmented-picker implementation stalled on the main thread during playback on this simulator. A process sample showed it in SwiftUI's segmented-control update. The final comparison uses ordinary buttons; playback through the study sequence was repeated successfully. This observation is not a general claim about every OS or Picker configuration.

The test installer retained an omitted resource when a package was installed over the existing app during this run. That first missing-resource probe therefore still imported successfully and was not counted as a negative-test pass. Checking the actual installed resource, temporarily moving it aside with a restore guard, and relaunching exercised the intended failure path.

## Still not validated

No production character has been selected, no reviewed skating clip has been imported, and no Blender/Maya/other DCC export pipeline has been tested. The fixture is not a general-purpose retargeter and does not validate arbitrary skeletons, animation blending, facial animation, detailed garment deformation, self-collision, realistic blade/edge mechanics, or body balance. Its simple material groups are not a production outfit system.

Physical-iPhone/iPad performance, memory/energy budgets, camera readability with final art, expert review, and production-asset rights remain acceptance gates in the [animation pipeline](animation-pipeline.md).
